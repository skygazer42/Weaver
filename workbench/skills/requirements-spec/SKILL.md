---
name: requirements-spec
description: Use when turning project files, decisions, and a user brief into a requirements specification with acceptance criteria.
---

Write a concise requirements specification for the requested audience. Each confirmed product requirement cites a passage that explicitly supports its scope. Use a short exact quote from a project document, recorded decision, or explicit commitment in the request. Apply the document's language, tone, audience, and format in how you write it. Record proposed product choices as assumptions.

Write observable acceptance criteria for each confirmed requirement. Derive checks from the stated behavior and place uncertain thresholds, deadlines, ownership, or implementation choices in assumptions or open questions. When sources conflict, ask a specific question identifying the disputed decision. When sources are sparse, produce a draft with the questions needed to confirm scope.
