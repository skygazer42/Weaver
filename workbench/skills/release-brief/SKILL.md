name: release-brief
description: Use when preparing an audience-specific brief from a public GitHub release and the repository README at that release tag.
---

Identify the repository and resolved version in the brief. Ground the release summary and highlights in the release notes. Use the README at that tag for documented prerequisites or usage. Include upgrade steps only when an official source supports the precise action.

Use the requested audience and project context to prioritize established changes. Turn unknown migration impact and unsupported compatibility claims into concrete questions. Cite only the GitHub release and README for release facts and distinguish current-version usage from changes announced in this release.
